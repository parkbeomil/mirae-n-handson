# legacy/item-bank-php 비즈니스 규칙 후보

- 작성일: 2026-09-29
- 범위: 분석 계획의 4단계(비즈니스 규칙 후보)다. 대상은 `legacy/item-bank-php` 의 코드와, 그 코드가 조회하는 뷰 정의(`db/mariadb/init/01-schema.sql`)다.
- 근거는 `파일:줄번호` 로 적는다. 모듈 안 파일은 `legacy/item-bank-php/` 를 뺀 경로(예: `search.php:215`)로 쓰고, 모듈 밖 파일은 저장소 루트 기준 경로로 쓴다.
- 선행 문서: `docs/item-bank/ARCHITECTURE.md`(진입점 · 의존 관계), `docs/item-bank/ERD.md`(데이터 흐름)
- 작성 원칙
  - 코드의 조건문 · SQL에 있는 것만 규칙으로 올렸다.
  - 근거가 주석뿐인 내용은 규칙으로 올리지 않고 §6에 "주석만 있음"으로 모았다.
  - 주석과 코드가 다르면 코드를 기준으로 규칙을 쓰고, 주석 내용은 비고에 남겼다.
  - 상태 코드의 뜻(`'A'` = 공개 등)은 스키마 주석(`db/mariadb/init/01-schema.sql:26`)에만 있다. 그래서 규칙 문장에는 코드 값을 쓰고, 뜻은 비고에 적었다.
  - DB 동작(콜레이션, PK 충돌 등)에 기대는 결과는 실행해서 확인하지 않았다. 규칙 문장에는 넣지 않고 비고에 "실행 확인 안 함"으로 적었다.
- **수정 경로 없음:** 이 모듈에는 문항 수정 화면도, UPDATE 문도 없다(`ERD.md` §3.3 · §6과 같은 검색 결과). 그래서 "수정 시 검증" 규칙은 없다.
  - 검색 패턴: `(update|delete from|insert into)\s+(item|unit|tag|item_tag)\b`
  - 검색 범위: `legacy/` · `modern/api/src` · `characterization/`
  - 결과: INSERT 2건만 나왔다(`register.php:93`, `:105`).

## 1. 검색 조건 조합 (`search.php`)

- 비고: `OR` 로 묶는 조건은 키워드의 제목 · 지문 두 컬럼뿐이다(BR-03).

## 7. 검증 이력

`docs/item-bank/CROSS-CHECK.md`(독립 추출본, CX-01~29)와 교차 검증했다(2026-09-29). 서로 다른 항목은 코드를 기준으로 판정했다.

- 2026-09-29 BR-09: CX-06 반영. 난이도 5는 건수 조회에서도 빠진다는 내용과 근거 `search.php:526` 을 추가했다.
- 2026-09-29 BR-11: CX-08 반영. `05` 처럼 정규식은 통과하지 못해도 `(int)` 변환값이 1~5인 값은 해당 난이도 결과가 나온다는 비고를 추가했다.
- 2026-09-29 BR-14: CX-10의 "미등록 태그는 결과 0건" 단정은 채택하지 않았다. 판정 근거인 `tag` 콜레이션 `_ci`(`db/mariadb/init/01-schema.sql:40`)를 비고에 추가했다.
- 2026-09-29 BR-24: CX-17의 "0 이하는 경고 없음"은 채택하지 않았다. 음수는 `search.php:337` 정규식에 걸려 경고가 붙으므로, 이를 규칙 문장에 명시하고 근거 코드 `:337`, `:340` 을 추가했다.
- 2026-09-29 BR-15 · BR-34: 유지. CX-12 · CX-24는 뷰 정의를 읽지 않아 "확인 불가"로 남겼다. 뷰 조건 `WHERE i.status = 'A'`(`db/mariadb/init/01-schema.sql:70`)로 코드상 확인되므로 바꾸지 않았다.
