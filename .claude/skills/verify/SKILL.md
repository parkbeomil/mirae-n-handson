# 검증: 승인 · 반려 판정

검증 대상: $ARGUMENTS

- 위 줄이 비어 있으면 `git diff upstream/main...HEAD` 를 대상으로 삼는다.
- 이 Skill 은 **만든 세션과 분리된 새 세션**에서 쓴다. 판정만 하고 코드는 고치지 않는다.
- 경로는 모두 **저장소 루트** 기준이다(Skill 폴더 기준이 아니다).

## 절차

1. **요청 범위 확인.** 무엇을 요청했는지 한 문장으로 받는다. 주어지지 않았으면 **판정하지 말고 먼저 질문한다.** 범위를 모르는 채 "요청 범위 이탈 없음"을 충족으로 쓰지 않는다.
2. **변경 파일 목록과 diff 읽기.** `git diff --stat <대상>` 으로 목록을 먼저 보고, 파일마다 diff 를 읽는다. patch 파일이면 `git apply --stat` 으로 목록을 뽑는다.
3. **체크리스트 대조 — reviewer Sub-agent 에 위임.** 직접 대조하지 않는다. reviewer 에게 비교 범위(검증 대상)와 요청 범위를 그대로 넘긴다. reviewer 는 저장소 루트의 `templates/approval-checklist.md` 를 읽고 항목마다 충족 · 미충족 · 확인 필요 중 하나로 표시해 이슈 목록과 함께 보고한다. 심각도 정의도 그 파일을 따른다.
4. **테스트 실행 — tester Sub-agent 에 위임.** 직접 실행하지 않는다. tester 에게 변경된 폴더와 아래 명령을 넘기고, 변경된 폴더의 테스트만 실행하게 한다. 새 로직에 테스트가 없으면 테스트 파일을 추가하게 하고, 실행 결과(통과 · 실패 수, 실패한 테스트 이름, 추가한 테스트 파일)를 돌려받는다. 아래 명령은 저장소 루트에서 시작한다.
   - `modern/api` 가 바뀌었으면 `cd modern/api && ./gradlew test`
   - `modern/web` 이 바뀌었으면 `cd modern/web && npm test`
   - 이관 코드가 바뀌었으면 `characterization` 에서 두 번 실행한다.
     - 레거시 대상: `cd characterization && npm test`
     - 새 API 대상: `cd characterization && TARGET_BASE_URL=http://localhost:8080 npm test`
   - 실행할 수 없었으면(서버 꺼짐, 의존성 미설치) 그 사실을 적고 사람에게 기동을 요청한다. 실행하지 않고 통과했다고 쓰지 않는다.
5. **승인 기준 판정.** reviewer 와 tester 두 보고를 받은 뒤 메인 세션이 체크리스트의 네 기준(테스트 통과 / 치명 이슈 0건 / 요청 범위 이탈 없음 / 컨벤션 준수)을 하나씩 최종 판정한다. 하나라도 미충족이면 반려다. 두 보고가 엇갈리면 엇갈린 지점을 그대로 적고, 판정하지 말고 사람에게 묻는다.

- reviewer 또는 tester Sub-agent 가 없는 환경에서는 3 · 4단계를 기존 방식대로 직접 수행한다.

## 출력 형식

```
판정: 승인 | 반려

| 기준 | 결과 | 근거 |
|---|---|---|
| 테스트 통과 | 충족 / 미충족 | 실행 명령과 통과 · 실패 수 |
| 치명 이슈 0건 | 충족 / 미충족 | 치명 이슈 번호 |
| 요청 범위 이탈 없음 | 충족 / 미충족 | 요청 문장 vs 변경 파일 목록 |
| 컨벤션 준수 | 충족 / 미충족 | 위반 항목 번호 |

이슈 목록
| # | 심각도 | 파일:줄번호 | 근거 | 수정 방향 |

확인 필요
- (근거 줄번호를 댈 수 없는 지적)
```

- 이슈 한 건은 심각도(치명 / 경고 / 제안) · 파일:줄번호 · 근거 · 수정 방향 순서로, 네 항목을 모두 채운다.
- 이슈가 0건이면 경고 · 제안 수준까지 한 번 더 본 뒤에 0건으로 보고한다.

## 사용량 절약

- 테스트 출력은 **통과 · 실패 수와 실패한 테스트 이름만** 남긴다. 전체 로그를 대화에 싣지 않는다.
- diff 는 파일 단위로 읽고, 판정에 쓰지 않는 부분을 대화에 옮겨 적지 않는다.

## 하지 말 것

- 코드를 수정하지 않는다(tester 가 추가하는 테스트 파일은 예외). 보고만 한다.
- 근거 줄번호를 댈 수 없는 지적은 이슈로 올리지 않고 "확인 필요"로 남긴다.
- 테스트를 실행하지 않고 통과했다고 쓰지 않는다.
- 체크리스트 항목을 이 파일이나 답변에 통째로 옮겨 적지 않는다. 항목은 `templates/approval-checklist.md` 에서 읽는다.
