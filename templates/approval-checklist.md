# 승인 체크리스트 v1

버전: v1. 팀 기준을 반영했다.
AI 가 만든 변경분 · 외주사 PR 을 머지하기 전에 리뷰어가 대조하는 목록이다. 네 기준이 **모두** 충족되어야 승인이다. 하나라도 미충족이면 반려.

## 심각도 정의

- **치명** — 아래 네 가지 중 하나. 1건이라도 있으면 반려.
  - 비밀값 노출
  - 데이터 손실
  - 인증 우회
  - SQL 문자열 조립
- **경고** — 치명은 아니지만 `CLAUDE.md` 컨벤션이나 다음 변경의 안전성에 걸리는 문제. 경고 자체는 승인 · 반려에 영향을 주지 않는다. 단 §4 반려 항목 위반은 이슈 목록 심각도 칸에 '경고'로 적더라도 ④ 미충족이라 반려다.
- **제안** — 더 나은 방법이 있다는 의견. 승인 · 반려에 영향을 주지 않는다. 목록으로만 남긴다.

이슈 한 건은 심각도 · `파일:줄번호` · 근거 · 수정 방향 네 항목으로 적는다. 근거 줄번호를 댈 수 없는 지적은 "확인 필요"로 따로 둔다.

## 1. 테스트 통과

- [ ] 변경된 모듈의 테스트 명령을 실제로 실행했다(실행하지 않고 통과라고 쓰지 않는다).
- [ ] 실행 결과에 실패 · 오류가 0건이다.
- [ ] 새로 추가한 public 메서드(getter · setter · 생성자 · record 접근자 제외)마다 그 메서드를 호출하는 테스트가 1개 이상 있다.
- [ ] 기존 테스트를 지우거나 건너뛰게(`skip`, `@Disabled`) 바꾼 곳이 없다.

## 2. 치명 이슈 0건

- [ ] 비밀번호 · 토큰 · 키가 코드 · 설정 · 테스트 픽스처에 리터럴로 들어 있지 않다.
- [ ] SQL 을 문자열로 이어 붙여 만드는 곳이 없다(파라미터 바인딩 사용).
- [ ] 요청에 없는 데이터 삭제 · 덮어쓰기(`DELETE` · `TRUNCATE` · 조건 없는 `UPDATE` · `deleteAll`)가 새로 생기지 않았다.
- [ ] 인증 · 권한 검사를 제거하거나 건너뛰게 바꾼 곳이 없다.

## 3. 요청 범위 이탈 없음

- [ ] 요청 문장이 한 문장으로 확인되었다(없으면 판정하지 않고 먼저 묻는다).
- [ ] 변경 파일 목록의 모든 파일이 요청 문장으로 설명된다.
- [ ] 변경된 파일 안에서 import 정리를 제외하고, 요청 문장으로 설명되지 않는 코드 변경(리팩토링 · 로그 문구 · 이름 변경 · 포맷팅)이 0건이다.
- [ ] 의존성 추가 · DB 스키마 변경 · 설정 파일 변경이 있다면 요청에 포함돼 있었다.

## 4. 컨벤션 준수

- [ ] 팀 `CLAUDE.md` 의 코딩 컨벤션과 금지 사항을 대조했다(`convention-check` Skill 이 있으면 그 결과를 쓴다).

반려 항목 — 하나라도 아니오면 ④ 미충족:

- [ ] 컨트롤러에서 Repository · SQL 을 직접 호출하는 곳이 없다.
- [ ] 본문이 비었거나 주석뿐인 `catch` 가 없다.
- [ ] `System.out` · `System.err` · `printStackTrace()` · `console.log` 같은 임시 출력이 남아 있지 않다.
- [ ] 새 `@Entity` 클래스 · `JpaRepository` 를 상속한 인터페이스 · `@Query` · 리포지토리 메서드 선언이 변경분에 없다(기존 리포지토리를 호출만 하는 것은 허용).

경고 항목 — 아니오여도 ④ 는 충족이다. 이슈 목록에 경고로 남긴다:

- [ ] 클래스 · 메서드 · 필드 이름이 팀 `CLAUDE.md` 의 네이밍 규칙을 따른다.
- [ ] 위 반려 항목 밖의 팀 `CLAUDE.md` 컨벤션(예: 새 숫자 리터럴의 상수화, 로그 규칙) 위반이 없다.

## 판정 형식

첫 줄에 `판정: 승인` 또는 `판정: 반려`. 이어서 네 기준의 충족 · 미충족 표, 그다음 이슈 목록(심각도 · `파일:줄번호` · 근거 · 수정 방향). 코드는 수정하지 않는다.
