# 승인 체크리스트 v0

버전: v0 (골격). 팀 기준을 반영해 v1 로 올린다.
AI 가 만든 변경분 · 외주사 PR 을 머지하기 전에 리뷰어가 대조하는 목록이다. 네 기준이 **모두** 충족되어야 승인이다. 하나라도 미충족이면 반려.

## 심각도 정의

- **치명** — 그대로 머지하면 서비스나 데이터에 피해를 줄 수 있는 문제. 1건이라도 있으면 반려.
- **경고** — 지금 고치지 않아도 동작하지만 다음 변경에서 사고가 될 가능성이 있는 문제. 승인 여부는 리뷰어가 판단한다.
- **제안** — 더 나은 방법이 있다는 의견. 승인 · 반려에 영향을 주지 않는다. 목록으로만 남긴다.

이슈 한 건은 심각도 · `파일:줄번호` · 근거 · 수정 방향 네 항목으로 적는다. 근거 줄번호를 댈 수 없는 지적은 "확인 필요"로 따로 둔다.

## 1. 테스트 통과

- [ ] 변경된 모듈의 테스트 명령을 실제로 실행했다(실행하지 않고 통과라고 쓰지 않는다).
- [ ] 실행 결과에 실패 · 오류가 0건이다.
- [ ] 테스트가 충분하다.
- [ ] 기존 테스트를 지우거나 건너뛰게(`skip`, `@Disabled`) 바꾼 곳이 없다.

## 2. 치명 이슈 0건

- [ ] 비밀번호 · 토큰 · 키가 코드 · 설정 · 테스트 픽스처에 리터럴로 들어 있지 않다.
- [ ] SQL 을 문자열로 이어 붙여 만드는 곳이 없다(파라미터 바인딩 사용).
- [ ] 데이터를 지우거나 덮어쓰는 코드가 새로 생겼다면 요청에 그 내용이 명시돼 있다.
- [ ] Actuator 가 `health` 외 엔드포인트(`env` · `configprops` · `heapdump`)를 노출하지 않는다.
- [ ] DB 연결 설정에 `useSSL=false` · `allowPublicKeyRetrieval=true` 가 운영용으로 들어 있지 않다.
- [ ] 오류 응답 · 로그에 스택트레이스 · SQL 바인딩 값 등 내부 정보가 실리지 않는다(`include-stacktrace` · `show-sql` · 바인딩 TRACE).
- [ ] 운영 설정에 H2 콘솔 · devtools · Swagger UI 노출이 없다.
- [ ] 신규 · 변경 엔드포인트의 외부 입력을 서버에서 검증한다(타입 · 범위 · 길이 · 허용 목록).
- [ ] 심각한 문제가 없다.

## 3. 요청 범위 이탈 없음

- [ ] 요청 문장이 한 문장으로 확인되었다(없으면 판정하지 않고 먼저 묻는다).
- [ ] 변경 파일 목록의 모든 파일이 요청 문장으로 설명된다.
- [ ] 요청과 무관한 변경이 지나치게 많지 않다.
- [ ] 의존성 추가 · DB 스키마 변경 · 설정 파일 변경이 있다면 요청에 포함돼 있었다.

## 4. 컨벤션 준수

- [ ] 팀 `CLAUDE.md` 의 코딩 컨벤션과 금지 사항을 대조했다(`convention-check` Skill 이 있으면 그 결과를 쓴다).
- [ ] 컨트롤러에서 Repository · SQL 을 직접 호출하는 곳이 없다.
- [ ] 예외를 잡고 아무 처리 없이 넘기는 곳이 없다.
- [ ] 로그 · 응답에 학생 식별자 · 이메일 · 토큰 원문이 없다(내부 숫자 id 사용).
- [ ] 컨트롤러가 `@Entity` 를 반환하거나 요청 본문으로 받지 않는다(`record` DTO 사용).
- [ ] `System.out.println` · `console.log` 같은 임시 출력이 남아 있지 않다.
- [ ] 코드가 팀 스타일에 적절하게 맞는다.

## 판정 형식

첫 줄에 `판정: 승인` 또는 `판정: 반려`. 이어서 네 기준의 충족 · 미충족 표, 그다음 이슈 목록(심각도 · `파일:줄번호` · 근거 · 수정 방향). 코드는 수정하지 않는다.
